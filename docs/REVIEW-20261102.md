# 2026-11-02 修复与子代理审查

修改前恢复点：`f9a9ca90d3385b3895183b1a188a0f97f0ced590`。本轮范围仅为格式错选、安装时关闭 Explorer 及审查发现的相关缺陷；未新增转换入口或设置页面。

## 已定位的现象

本机已安装主程序、Shell DLL 均为 3.0.0，Explorer 也加载该路径的旧 DLL，但全局菜单快照曾指向另一份 3.0.1 主程序。旧 DLL 在带 Unicode 标志的数字命令调用中误读空 `lpVerbW`，发出第一个预设 GIF。因此主程序虽显示成功，生成的格式并非点击的格式。

3.0.2 保留已修正的命令分发，使用独立 DLL 路径和新的内部 COM 标识，不覆盖已驻留的旧 DLL。注册后通知 Windows 关联变更。快照更新优先使用注册的主程序路径，开发目录运行不再在初始化时改写菜单入口。

## 两个子代理只读审查结果

| 审查项 | 发现 | 修正和证据 |
|---|---|---|
| 菜单与 Shell | ANSI 帮助文本使用 ASCII / UTF-8，不符合 Windows ANSI 宿主编码约定 | 两种 DLL 均改为 CP_ACP；原生宿主比对中文 ANSI / Unicode 帮助文本 |

| 注册与安装 | 注册前写快照，不完整发行包失败后会影响正在使用的菜单；中途失败可能只恢复快照而留下部分新注册 | 完整注册预检；写入后失败恢复快照及本次涉及的 COM 类、handler、Executable；不完整目录与注册中途故障注入回归均通过，恢复失败会明确报告 |
| 注册与安装 | MajorUpgrade 默认事务顺序与原版不同 | 恢复上游 Schedule="afterInstallInitialize"；安装失败回滚完整场景尚未验收 |
